# Oklab Neutral 贝塞尔褪色实验

此实验只替换 Oklab Neutral 的高光颜色保留量，保持 max-RGB 亮度肩部、AP0 → BT.709 输入适配、root-LMS 插白和 RGB 归一化。WGSL 辅助函数用于独立 GPU 实验，未注册为默认 DRT。

设肩部进度为 `P = 1 - tail`，插白权重为 `H(P)`，颜色保留量为 `R = 1 - H`。贝塞尔横坐标控制点均匀排列，所以参数直接等于 `P`，无需求解反函数或增加迭代。

当前曲线 `H(P) = P³(3 - 2P)` 本身就是四次贝塞尔，纵坐标控制点为 `[0, 0, 0, 0.75, 1]`。精确改写成贝塞尔形式不会改变输出。

实验比较：

| 曲线 | 插白权重的纵坐标控制点 | 白端保留量斜率 κ |
| --- | --- | --- |
| 当前四次 | `[0, 0, 0, .75, 1]` | 1 |
| 四次宽白端 | `[0, 0, 0, .4375, 1]` | 2.25 |
| 三次宽白端 | `[0, 0, 0, 1]` | 3 |
| 五次折中 | `[0, 0, 0, .55, .55, 1]` | 2.25 |
| 五次强保色 | `[0, 0, 0, .4, .4, 1]` | 3 |

三次宽白端与四次 `[0, 0, 0, .25, 1]` 精确相同。当前四次升阶后的五次控制点为 `[0, 0, 0, .3, .8, 1]`，也精确保持原输出。

五次折中的多项式为 `H(P) = 5.5P³ - 8.25P⁴ + 3.75P⁵`；在 shader 中直接计算稳定的保留量：

```text
R(r) = r * [2.25 + r * (-4.5 + r * (10 + r * (-10.5 + 3.75r)))]
```

所有控制点单调排列，权重保持在 `[0, 1]`。其褪色在肩部起点的前两阶导数为零。曲线形状的凸性不能直接保证最终 Oklab L–C 轨迹凸性，因为后续仍有亮度缩放和 RGB 最大通道归一化。

## 测量范围

- 61 条 BT.709 离散色彩曝光射线，低、中、高压缩起点及 SDR/HDR。
- 输入色度递减的绿色、青色、品红色混向灰色的路径，包含极端 HDR。
- 真实样片 `ACES_OT_VWG_SampleFrames.0081.exr` 的绿色/青色房间，输入按应用的 fp16 上传和 AP0 → BT.709 适配。
- 独立 f64 贝塞尔求值与真实 wgpu 输出对照。

SDR、斜率 1 时，低压缩起点 `.1` 配合 `Highlight reach = 10.390 EV`，肩部幂次约 `.6282560668`；默认起点 `.6`、reach `10 EV` 时约 `.4294394792`。比较颜色算法时保持同一组亮度参数。

白端 `R ≈ κr`。在 SDR、斜率 1 下，有 `1 - RGBout ≈ r[(1-j)white + κDcolor]`。提高 κ 能扩大白端开口，但也加强浅色高光的颜色。单一的亮度进度曲线不能自动区分高饱和端与近中性端。

离线 f64 测量中，低起点 `.1` 的 60 条非灰射线，白端相对灰轴的夹角中位数由 `18.61°` 增至 `26.48°`（κ=2.25）；这是渐近端点角度，不代表 fp16 在无限接近白点时仍可区分所有点。

在默认 `.6 / 10 EV` 下，五次折中把绿色 `32 → 灰色 4` 的输出色度反弹从约 `11.15%` 降至 `2.38%`；青色从 `17.41%` 降至 `5.45%`，品红从 `8.93%` 降至 `1.51%`。这些比例按路径的首点色度归一化，首点本身也变得更饱和，不能仅凭相对比例判断整个色带减弱。极端 `2048 → 灰色 1` 仍存在明显色度反弹。

扩大白端的四次曲线 κ=2.25，在低起点样片暖色近白区将色度中位数提高到当前的 `1.64 倍`，青色墙面局部明度回落由约 `.00364` 增至 `.02213`。

五次折中改善部分混色，但真实样片仍有代价：默认设置下暖色近白区的色度中位数为当前的 `1.212 倍`，青色第一行墙面的局部 L 回落由 `.02706` 增至 `.03991`；低起点时分别为 `1.404 倍` 和 `.00364 → .01637`。第二行墙面的回落有很小改善，无法据此认为整张图得到修复。

RTX 4090 / Vulkan 的 GPU 实验通过：5 条曲线 × 2 组亮度参数 × SDR/HDR 峰值 `1 / 4 / 64`，输出有界且与独立 f64 贝塞尔求值一致；暗部和灰轴保持逐像素相同。考虑输入/输出 fp16 后，默认绿色混灰的实测反弹约 `11.56% → 2.60%`，极端青色混灰仍约 `14.64 倍 → 7.42 倍`。这与连续 f64 试算的结论一致，但近白色度非常小时，相对比例会受 fp16 舍入影响。

贝塞尔是可调节褪色形状的低成本工具。所测单变量曲线仍不足以同时解决白端收窄、混色反弹和近白明度次序问题。当前结构在混色中随最大 RGB 分量下降而恢复颜色保留量；改变控制点可以减缓恢复，却没有去掉这一耦合。下一步需根据源颜色饱和度区分近中性与高饱和端的响应。

在项目目录的 PowerShell 中：

```powershell
$env:DRT_BEZIER_REPORT_DIR = Join-Path (Get-Location) '.cache/bezier-audit'
cargo +stable test --locked oklab_bezier -- --include-ignored --test-threads=1 --nocapture
```
